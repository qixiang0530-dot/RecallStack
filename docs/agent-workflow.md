# RecallStack Agent Workflow

本文记录 v0.2 如何使用 Agent 辅助完成产品拆解、实现与验证。这里的“Agent 工程架构”指开发协作流程和可替换 Provider 边界，不代表当前应用已接入真实 LLM。

## 1. 从想法到可验证需求

项目先把“像背单词一样背 Java 八股”收敛为一条可验证闭环：

```text
今日任务 -> 主动回忆 -> 查看答案 -> 四档评分 -> FSRS 安排复习
```

Agent 用于梳理用户目标、首版边界和验收标准。每项需求都转化为可观察结果，例如“个人牌组与内置牌组隔离”对应独立 `deckId`、筛选界面和数据层测试。

## 2. 从需求生成实现计划

实现按风险顺序拆分：

1. 先定义 `MaterialInput`、`CardDraft` 和 `CardGenerationProvider` 契约。
2. 用测试固定本地 Markdown 的解析规则和降级行为。
3. 迁移 Dexie，再实现审核、确认和备份。
4. 最后接入 React 页面、移动端样式和端到端流程。

这种顺序先稳定数据边界，再构建界面，减少 UI 完成后返工底层模型的概率。

## 3. Agent 辅助测试

功能使用 Red-Green-Refactor 节奏实现：先写失败测试，确认失败原因与缺失行为一致，再写最小实现并运行回归。

主要覆盖：

- Markdown 标题、段落、列表和无明确问题的降级草稿
- 重复确认、批量确认和个人牌组隔离
- Dexie v2 到 v3 迁移与旧备份兼容
- 首次引导、键盘操作、输入框快捷键隔离和完成摘要
- 桌面与 Pixel 7 的完整拆卡和学习路径

## 4. 浏览器验证与回归

Agent 通过 Playwright 操作真实 Vite 页面，而不是只依赖组件测试。验证过程包括：

1. 在桌面视口完成首次引导和 Java 卡片学习。
2. 查看上一题并替换评分，刷新后检查会话位置。
3. 粘贴 Markdown，审核并确认个人卡片。
4. 切换个人牌组并刷新页面确认持久化。
5. 导出并恢复 JSON 备份。
6. 切换到 Pixel 7 尺寸检查导航、表单、按钮和内容是否重叠。

## 5. Provider 接口边界

```ts
type CardGenerationProvider = {
  generate(input: MaterialInput): Promise<CardDraft[]>
}
```

`LocalMarkdownProvider` 是 v0.2 的默认实现。它只负责把输入转换为草稿，不写入正式卡片表。未来 `LlmCardGenerationProvider` 可以替换生成策略，但必须输出相同的 `CardDraft`，继续经过现有审核和确认流程。

Provider 不负责 FSRS、牌组写入、备份或 UI 状态。这些职责由现有仓储和页面层承担，避免模型接入扩散到整个应用。

## 6. 为什么生成内容必须审核

面试知识卡片要求问题边界清楚、核心回答可复述、细节版本准确。无论是本地规则还是 LLM，都可能产生拆分过细、上下文丢失、关键词错误或事实偏差。

因此 RecallStack 把生成结果定义为 `CardDraft`：必要字段不完整时不可确认，用户可以编辑、删除或批量确认，只有确认后的内容才转换为 `source: 'user'` 的正式卡片并进入学习队列。
